Fixation-word bug: root-caused and fixed, 2026-09-13. Not silicon, not CDC/electrical — an earlier conclusion on this page said exactly that, and it was wrong (see model/SCALE-UP-LOG.md's own in-place correction). The real cause: a silently-truncating 11-bit rd_addr register (needed 14 bits for VOCAB=16384), shared between a diagnostic readback port and a production firmware fallback (remask_pick_excluding()) that masked-argmax scans all 16,384 head logits whenever the repetition guards need to replace a stop token picked too early. Pre-fix, that scan's read of vocab id 2213 ("care") silently aliased to id 165's own logit — the single highest value in the entire array — so "care" won the fallback by inheriting a value that belonged to a different, filtered-out index. Fully deterministic, nothing to do with silicon margin. Full derivation: fabric/genesys2/FIXATION-WORD-CDC-INVESTIGATION.md §8 item 14 / §10. The hardware panels below are a fresh post-fix capture (same 5×5 methodology as the original, pre-fix run) — see the fixation-term counts below for the before/after. Separately, unrelated to the fix: not an apples-to-apples weight comparison — the board runs the QAT/INT4 checkpoint; the plain GPT.generate() class can't load that quantized state dict, so the software side runs the pre-QAT FP checkpoint (ckpt_stepC_d128_v16384.pt) at the board's calibrated temperature instead, the closest practical proxy, not a bit-exact one.

The pattern the bigram detector couldn't catch: before and after

The flagged-rate score alone made the real (pre-fix) board look cleaner than its own software proxy — reading the samples showed why: the board was substituting odd, non-sequitur words as story subjects/objects, a different failure mode than bigram looping that is_degenerate mostly can't see (single-word insertions, not repeated pairs).
